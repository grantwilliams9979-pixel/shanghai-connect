# Shanghai Connect

**Shanghai Connect** is a bilingual English/Chinese platform that helps expats, tourists, international students, business travellers, and foreign residents navigate life in Shanghai.

**Tagline:** Shanghai starts here.

**Live site:** [shanghai-connect.com](https://shanghai-connect.com) — `www` 308-redirects to the apex, which is the canonical host.

## Vision

Shanghai can be difficult to navigate for newcomers because important information is scattered across WeChat groups, blogs, forums, outdated articles, and word of mouth. Shanghai Connect brings essential Shanghai information together in one trusted, bilingual, easy-to-use place — less a traditional directory, more a **digital concierge for Shanghai**.

The first release is the **Shanghai Starter Pack**: curated, editor-managed guides covering essential apps, VPNs, neighbourhoods, transportation, foreign groceries, and must-know information for arriving in and living in Shanghai. User accounts, reviews, and community features come in later phases.

## Local development

There is no build step, but internal links use extensionless clean URLs, so opening `index.html` directly in a browser will break navigation. Serve the folder with a clean-URL-aware server instead:

```sh
npx serve .        # clean URLs on by default
# or
vercel dev         # uses vercel.json
```

Note: `npx serve` does not apply the `vercel.json` redirects, so legacy `.html` URLs will not resolve locally.

## Sitemap

`sitemap.xml` is generated, not hand-edited. It lists every `<route>/index.html` in the repo and drops any page carrying a `noindex` robots meta tag, so adding a page is enough to get it into the sitemap.

```sh
python3 scripts/generate_sitemap.py           # rewrite sitemap.xml
python3 scripts/generate_sitemap.py --check   # exit 1 if it is stale
```

The [Update sitemap workflow](.github/workflows/sitemap.yml) runs the generator on every push to `main` that touches a page, and commits the result if it changed — so new pages appear in the sitemap without any manual step. `<lastmod>` comes from each page's last commit date.

## Adding a page

Pages are hand-authored HTML with no template system, so every new `<route>/index.html` carries its own `<head>`. Copy the closest existing page and keep these invariants — search coverage depends on them:

- One `<h1>`. A unique `<title>` of 60 characters or fewer, and a unique meta description of 140–160.
- `<link rel="canonical">` on the HTTPS clean URL, with an `og:url` that matches it exactly.
- `og:image` pointing at the page's own hero image, alongside `og:title`, `og:description`, `og:type`, and `twitter:card`.
- No `hreflang`. The language toggle is client-side on a single URL, so alternates would not be self-canonical and Google ignores them.
- Link the page from somewhere real: a related-guides block on a sibling page, and the homepage `<noscript>` lists in [index.html](index.html) if it belongs there. The homepage's guide and neighbourhood grids are built by [script.js](script.js), so those `<noscript>` lists are the only crawlable links the homepage has — removing them orphans whatever they pointed to.
- Nothing to do for the sitemap. It regenerates on push.

## Technology

**Current:** static HTML/CSS/JS, no framework, hosted on Vercel with the custom domain `shanghai-connect.com`.

**Planned** (documented in [docs/product-technical-plan.md](docs/product-technical-plan.md)): Next.js + TypeScript + Tailwind, Sanity CMS, PostgreSQL in later phases, Typesense search, Cloudflare in front of Vercel.

## Design

The site should feel like **Lonely Planet × Apple × Notion**, with the usability of Airbnb and the discoverability of Google Travel. Mobile-first, fast, readable, accessible, SEO-friendly, and consistent with the design system in `styles.css`. The full inspiration list and design-system details are in [docs/product-technical-plan.md](docs/product-technical-plan.md); the working SEO and design rules are in [CLAUDE.md](CLAUDE.md).
